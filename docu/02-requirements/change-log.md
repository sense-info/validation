## 寫作原則

此文件用於記錄專案需求與變更歷程，確保每次功能增減都能追溯原因與影響範圍。

## 需求變更紀錄

### 需求 001：提供預設驗證規則
- 狀態：已完成
- 說明：支援常見的 required、email、numeric、min、max 等基本 rule
- 影響：為所有 PHP 專案提供通用驗證基礎

### 需求 002：支援陣列/巢狀欄位驗證
- 狀態：已完成
- 說明：支援 wildcard 及點格式的輸入鍵如 `skills.*.id`
- 影響：可驗證複雜資料結構

### 需求 003：支援自訂訊息與別名
- 狀態：已完成
- 說明：使用者可自訂欄位名稱與錯誤訊息
- 影響：提升可讀性與國際化準備

### 需求 004：支援自訂驗證 rule
- 狀態：已完成
- 說明：可透過 `addValidator()` 或 callback 註冊新的 rule
- 影響：擴充驗證能力且保持框架獨立

## 變更追蹤格式

每個需求變更宜含以下資訊：

- 變更日期
- 變更原因
- 影響範圍
- 相關檔案
- 驗證方式
- 回滾方案（若適用）
